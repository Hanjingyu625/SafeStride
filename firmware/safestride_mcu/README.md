# SafeStride MCU 펌웨어

이 스케치는 SafeStride MVP의 저수준 제어를 담당합니다. 휠 엔코더 값을
수집하고, 시리얼 세션을 검증하고, 명령 워치독을 적용하고, 휠 목표값을
제한하며, 두 개의 PID 루프를 실행합니다. 또한 엔코더의 정지·방향·과속
상태가 타당한지 검사하고 텔레메트리를 전송합니다.

안전을 위해 시작할 때는 모터 드라이버가 비활성화되어 있습니다. 시리얼이
다시 연결되거나 E-stop이 해제되었다는 이유만으로 자동 무장되지 않습니다.

이 참조 구현은 기본 AVR Uno/Nano 계열 보드를 대상으로 합니다. 해당
빌드에서는 부팅마다 증가하는 카운터를 EEPROM에 저장하고 AVR 하드웨어
워치독을 사용합니다. 같은 수준의 영구 boot-ID 및 워치독 코드를 해당
보드에 이식하기 전까지 non-AVR 빌드는 의도적으로 거부됩니다.

## 기본 핀 배치

다음은 Arduino Uno 계열 보드에서 사용할 수 있는 예시 핀입니다.

| 기능 | 핀 |
|---|---:|
| 왼쪽 엔코더 A (인터럽트) | 2 |
| 왼쪽 엔코더 B | 4 |
| 오른쪽 엔코더 A (인터럽트) | 3 |
| 오른쪽 엔코더 B | 7 |
| 왼쪽 모터 PWM | 9 |
| 왼쪽 모터 방향 | 8 |
| 오른쪽 모터 PWM | 10 |
| 오른쪽 모터 방향 | 12 |
| 모터 드라이버 활성화 | 6 |
| 상시 폐쇄형(normally-closed) E-stop 감지 | A0 |
| dead-man 스위치 | A1 |
| 배터리 감지, 기본값은 비활성화 | A2 |
| 왼쪽/오른쪽 전류 감지, 기본값은 비활성화 | A3/A4 |

컴파일하기 전에 `config.h`를 검토하세요. 특히 다음 사항을 확인해야 합니다.

- 엔코더 A 핀 두 개가 해당 보드에서 외부 인터럽트를 지원하는지 확인합니다.
- PWM 핀이 모터 또는 센서 라이브러리와 충돌하지 않는지 확인합니다.
- 구현된 A-channel `CHANGE` 카운팅 방식에 맞춰 **휠 출력축 1회전당**
  엔코더 카운트 수를 설정합니다.
- 휠을 앞으로 돌렸을 때 양수 텔레메트리가 나올 때까지 엔코더 부호를
  조정합니다.
- 양수 PID 출력이 각 휠을 전진시킬 때까지 모터 부호를 조정합니다.
- 엔코더와 모터의 부호를 각각 확인하기 전까지 `MAX_PWM`을 낮게
  유지합니다.
- 실제 엔코더와 구동계의 로그를 바탕으로 정지 상태 무장 대기시간과
  엔코더 무신호(no-edge), 역방향(reverse), 과속(overspeed) 임계값을
  조정합니다.
- 휠을 하나씩 들어 올린 상태에서 PID를 조정합니다.

## 전기적 안전

이 스케치의 E-stop 입력은 상태 진단과 보조 소프트웨어 정지만 담당합니다.
상시 폐쇄형(normally-closed) E-stop 접점은 이 MCU에 의존하지 않고도 모터
드라이버의 하드웨어 활성화 신호 또는 구동 전원을 차단하도록 배선해야 합니다.

모터 드라이버 활성화 입력을 설정된 비활성 레벨로 유지하는 외부
풀다운(pull-down) 저항을 추가하세요. active-low 드라이버라면
풀업(pull-up) 저항을 사용합니다. MCU의 전원이 꺼져 있거나, 부팅 또는
리셋 중이거나, 핀이 부동(floating) 상태일 때도 드라이버는 반드시
비활성화되어야 합니다. 로직 전압도
확인하세요. Arduino의 5 V 출력을 Raspberry Pi GPIO 입력에 직접
연결하면 안 됩니다.

모터 전원 전류가 Arduino를 통과하면 안 됩니다. 정격에 맞는 모터
드라이버, 퓨즈, 배선, 접지, 노이즈 억제 회로 및 전원을 사용하세요.
모터 EMI로 인해 USB가 리셋되거나 엔코더 입력이 손상될 수 있습니다.

## 상태 머신

```text
BOOT -> DISARMED -> ARMED
          ^           |
          |           +-> SAFE_STOP (시간 초과 또는 dead-man 해제)
          +--------------- 비활성 명령

모든 상태 -> ESTOP (물리 입력)
모든 상태 -> FAULT (드라이버/config 오류)
```

- 유효한 `SESSION_START`를 받아도 출력은 항상 비활성 상태로 유지됩니다.
- AVR 빌드는 리셋 이전 세션에서 버퍼에 남은 명령이 새 부팅과 일치하지
  않도록 EEPROM의 영구 부팅 카운터를 증가시킵니다. 애플리케이션이 해당
  EEPROM 영역을 이미 사용 중이라면 설정된 EEPROM 주소를 옮기세요.
- 활성화하려면 설정된 대기시간 동안 휠이 정지했다는 피드백이 확인되어야
  합니다.
- 활성 세션에서 이전보다 새로운 시퀀스를 가진 유효한 명령만 워치독을
  갱신합니다.
- 명령 워치독이 만료되면 버퍼에 있는 시리얼 명령을 해석하기 전에 세션을
  무효화합니다. 따라서 시간 초과 이전에 대기열에 쌓인 명령으로 다시
  무장할 수 없습니다.
- CRC 오류, 잘못된 형식의 패킷, 중복 패킷, 오래된 시퀀스 및 잘못된
  세션은 워치독을 갱신하지 않습니다.
- `SAFE_STOP`, `ESTOP`, `FAULT` 상태에서 `ARMED` 상태로 자동 복귀하지
  않습니다.
- 실행 중 발생한 엔코더 타당성 오류는 MCU를 리셋할 때까지 유지됩니다.
- 원인을 제거한 후 호스트가 비활성 명령을 보내야 하며, 운전자가 다시 명시적으로
  무장을 요청해야 합니다.
- 호스트 연결이 끊기면 명령 워치독이 출력을 정지하고 세션을 폐기하여
  새로운 HELLO 핸드셰이크가 시작됩니다.

## 빌드

이 스케치는 AVR Arduino core 라이브러리만 사용합니다. Arduino IDE에서
`safestride_mcu.ino`를 열고 정확한 보드와 포트를 선택한 다음 컴파일하고
업로드하세요.

Arduino CLI에서 Uno를 사용하는 예시는 다음과 같습니다.

```bash
arduino-cli compile --fqbn arduino:avr:uno firmware/safestride_mcu
arduino-cli upload --fqbn arduino:avr:uno -p /dev/ttyACM0 \
  firmware/safestride_mcu
```

`Serial`에 디버그 텍스트를 출력하지 마세요. 같은 포트에서 바이너리
프로토콜을 전송합니다. 진단에는 별도의 하드웨어 UART, LED 또는 디버거를
사용하세요.

## 센서 자리표시자

`readRangeLeftMm()`과 `readRangeRightMm()`은 유효하지 않은 값을 뜻하는
`0xffff`를 반환합니다. ROS 안전 설정은 기본적으로 거리 데이터를
요구하므로, 이 함수들을 실제 구현으로 교체하거나 바퀴를 들어 올린 벤치
시험에서 해당 요구사항을 명시적으로 비활성화하기 전까지는 주행이
차단됩니다.

배터리 및 전류 측정도 `config.h`에서 비활성화되어 있습니다. 통신에서
사용하는 센티널 값은 `0xffff`와 `INT16_MIN`이며, ROS는 이를 측정값
대신 사용할 수 없는 값으로 발행합니다.

비차단(non-blocking) 센서 드라이버를 사용하세요. 차단(blocking) 방식의
초음파 펄스 측정은 시리얼 해석과 모터 제어를 지연시켜 위험한 시간 제어
문제를 일으킬 수 있습니다.

## 최초 시험 절차

1. 모터 전원을 분리하고, 부팅 및 리셋 중에 EN이 설정된 비활성 레벨로
   유지되는지 확인합니다.
2. `/walker/status`에서 E-stop 및 dead-man 비트를 확인합니다.
3. 각 휠을 손으로 돌려 엔코더의 부호와 크기를 확인합니다. 두 휠이 설정된
   대기시간 동안 정지하기 전에는 무장 요청이 거부되어야 합니다.
4. 패킷을 손상시키거나 잘라서 보내고 워치독이 갱신되지 않는지
   확인합니다.
5. 휠을 들어 올리고 모터 전원을 연결한 다음, 한 번에 한 휠씩 낮은 PWM으로
   시험합니다.
6. 연속적인 0 명령으로 무장한 다음 매우 작은 목표값을 시험합니다.
7. USB를 분리하고 정해진 시간 안에 EN이 비활성화되는지 확인합니다.
8. 모든 연결을 해제했다가 다시 연결하고 자동으로 재시작되지 않는지
   확인합니다.
9. 무신호(no-edge), 역방향(reverse-direction) 및 지속적인 과속(overspeed)
   피드백을 주입하고, 이에 해당하는 엔코더 오류가 리셋할 때까지 유지되는지
   확인합니다.

현재 safe-stop 구현은 드라이버를 즉시 비활성화합니다. 이때 관성 주행,
제동 또는 유지 토크(holding torque) 해제 중 어떤 동작이 발생하는지는 모터 드라이버와
기구에 따라 달라집니다. 실제 보행기에 하중을 가하거나 사람이 의지하는
시험을 하기 전에 올바른 정지 동작을 정의하고 검증해야 합니다.
