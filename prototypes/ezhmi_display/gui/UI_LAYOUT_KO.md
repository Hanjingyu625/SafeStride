# SafeStride UI v2 — 사용자 스케치 기반

기준 LCD: 480 × 272, 가로. 상단 좌측 SafeStride 워드마크, 상단 우측 DEV 모드 버튼.
왼쪽 위 속도 / 왼쪽 아래 주행 여부 / 오른쪽 위 도로 상황 / 오른쪽 아래 경사 정보.
DEV 버튼은 비활성 상태이며 이벤트, 페이지 이동, 제어 기능이 없다.

색상은 Midnight 네이비 + 민트가 기본이다. 주의 상태는 앰버, 위험/정지는 코랄로 표시한다.
색상과 함께 O/X/? 및 설명을 표시한다. 모바일 390px 미만 미리보기만 높이를 늘려 글자를 보존한다.

## 화면 데이터

- 속도: km/h, 수신 무효 시 `--`. 압력 감지는 하단 보조 문구로 표시.
- 주행 여부: O 주행 가능, X 대기/정지, ? 수신 무효. 상태별 원인을 한 줄로 설명.
- 도로 상황: 현재 위치(시·구), 횡단보도 N/A / 진입 가능 / 대기 안내.
- 경사 정보: 평지 / 오르막 / 내리막 / 급경사, 부호 있는 각도 및 안내.
- 예시 시나리오의 `서울시 광진구`는 고정된 가상 위치이며 현재 위치를 조회하지 않는다.

## 부팅 및 전원

미리보기는 정상 주행 화면에서 시작한다. 전원 OFF를 누르면 화면 내용을 숨긴다.
전원 ON으로 바꾸면 로고 인트로가 2.2초 표시된 다음 선택된 상태 화면으로 돌아온다.
실제 LCD의 부팅 이벤트/타이머는 제조사 VisualTFT 문법 확인 후 이 동작을 이식해야 한다.

## 데이터 연결 시 구분할 사항

현재 HTML은 시각 디자인과 상태별 문구를 확인하는 시뮬레이터다. 실시간 UART 연결과
VisualTFT 네이티브 프로젝트가 아니다. 이번 UI 수정은 펌웨어의 정지/제어 판단을 변경하지 않는다.

- O/X는 실제 주행 허가 및 제동 상태에서 가져와야 한다. 압력 감지만으로 O를 결정하지 않는다.
- 수신 무효는 정지 확인과 다르므로 `? 확인 불가`로 표시한다.
- 교차로 진입 가능은 유효한 판단 데이터에서 받아야 한다. 단순 횡단보도 감지는 통행 허가가 아니다.
- 차체 pitch는 현재 기울기이며 전방 경사 예측값이 아니다. 급경사 예시 각도는 제어 임계값 정의가 아니다.
- 기존 32바이트 패킷에는 시·구 문자열이 없다. 위치 표시는 추후 Pi의 위치 이름 데이터와 별도 매핑이 필요하다.

미리보기 파일: `safestride-cockpit.html`.
