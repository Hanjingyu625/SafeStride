# 속도가 변하는 경우와 역치값

## 진행방향 반영 선택 (현재 작업 트리)

아래 과거의 방향 미사용 설명을 대체한다. GPS·IMU 융합이 유효한 방향을 반환하면
80m 이내에서 진행방향과 횡단축의 오차, 진행방향과 횡단보도 중심 방위의 오차가
각각 `candidate_heading_tolerance_deg=60°` 이하인 후보 중 가장 가까운 것을 선택한다.
가장자리 1m 이내에서는 중심 방위 조건만 면제한다. 예: 북쪽 진행 시 뒤쪽 5m
횡단보도보다 앞쪽 15m 횡단보도를 선택할 수 있다.
방향 없음·만료·비정상 수치이면 방향 조건 없이 가장자리 거리로 선택한다.
방향이 유효하지만 일치 후보가 없으면 선택을 보류한다. 회전 후 같은 GPS fix라도
방향 조건을 다시 평가한다. 멀어지는 후보 제외·복귀 조건과 횡단 중 고정은 유지한다.
선택된 방향은 API 신호 방향으로 직접 사용하지 않고 기존 지도 매핑을 거친다.
`selection_source`는 방향 사용 시 `nearest_heading`, 없으면 `nearest_distance`다.
정책 상태·진입 판단 대상은 달라질 수 있지만 목표속도 수치·PWM은 그대로이며
`motion_output_enabled=false`로 모터 출력은 비활성이다. 기준은 `707ff78` 이후
이 방향 선택 변경을 적용한 소스·설정이다.

## 2026-09-29 멀어지는 후보 제외 (현재 작업 트리)

현재 작업 트리는 아래 최근접 선택에 **멀어지는 후보 제외**를 추가한다.
- 횡단보도 가장자리 거리의 최근 6초 이력을 서로 다른 채택 GPS fix로 비교한다.
  최소 3개 관측·2초 이상에서 거리가 2m 이상 증가하고, 전반·후반 각각 0.5m 이상
  증가하며 인접 변화의 70% 이상이 -0.4m 이상이면 후보에서 제외한다.
- 다른 후보가 없어도 제외하여 선택을 해제한다. 남은 후보 중 80m 이내 최근접을 고른다.
  제외 후 정지해도 제외 상태를 유지하며, 같은 조건으로 2m 이상 가까워지는 추세가
  확인되면 복귀한다. 예: 15→16.2→17.4m를 2초간 관측하면 제외한다.
- GPS 관측 간격 3초 초과·시간 역전·노드 GPS 무효 처리 시 이력을 초기화한다.
  탐색 범위를 벗어난 후보의 제외 기록도 지운다. 중복 fix와 단일 점프 후 정지는
  지속 이탈로 인정하지 않는다. 재시작 후에는 새로 관측한다.
- 횡단 시작 전에는 후보 소실/교체로 기존 고정을 해제한다. 이미 횡단 중이면
  기존 통로 이탈·2초 확인 또는 정상 횡단 완료 조건까지 추적을 유지한다.
- 신호 판단 대상과 정책 상태는 바뀔 수 있으나 목표속도 수치·PWM·측정속도는
  변경하지 않는다. `motion_output_enabled=false`로 모터 명령은 비활성이다.

## 2026-09-29 잔여시간 만료 기반 조회 (현재 작업 트리)

이 절은 `977d550` 이후 잔여시간 조회 및 신호색 비교 제거를 적용한 코드·설정 기준이며, 아래 이전 신호
조회 주기·12초 캐시 만료·다중 방향 합의 설명보다 우선한다.

- 다른 방향 신호와 색이 다르다는 이유로 횡단보도 후보나 개별 신호를 제외하지 않는다.
  연결된 단일 방향만 판정하며 다른 방향의 더 짧은 잔여시간도 섞지 않는다.
  예: 연결된 북쪽 녹색 20초와 남쪽 빨강 60초가 함께 있어도 북쪽은 녹색 20초로 계산한다.
  방향 자체가 미확정이면 색과 관계없이 연결 확인을 기다린다.
- 선택 횡단보도 가장자리 20m 이내, 교차로 ID와 단일 보행 신호 방향을 확인하면
  현시와 잔여시간 API를 함께 조회한다. 빨강도 잔여시간을 받아 다음 조회를 예약한다.
  두 API이므로 정상 조회 한 번은 HTTP 요청 두 건이다.
- 최초 수용 시 원본 시각 나이 ≤12초, 미래 오차 ≤1초, 동일 교차로 및 두 원본 시각
  차이 ≤3초를 확인한다. 잔여시간은 API 단위 0.1초에서 초로 변환한다.
- 수용한 현시는 `원본 시각 + 잔여시간`까지 유지하고 로컬 시각으로 남은 시간을
  계산한다. 예: 원본 녹색 잔여시간 20초, 수신 지연 2초면 수신 후 18초 동안
  추가 조회 없이 계산한다. 초기 12초 기준은 수용 검사이며 수용한 카운트다운을
  12초에 끊지 않는다. 빨강 60초도 같은 방식으로 계산한다.
- 종료 시 신호를 미확정으로 바꾸고, 여전히 20m 안이며 방향이 확인된 경우 재조회한다.
  시간이 지났다는 이유로 빨강↔초록을 자동 전환하지 않는다. 중복 원본 시각은 종료
  시점을 연장하지 않는다. 단일 방향 미확정은 색이 같아도 진입 불허이며 조회도 보류한다.
- 초기 요청·실패·필수 정보 누락 재시도는 최소 3초 간격이고 진행 중 요청은 중복하지
  않는다. 서버 HTTP 429/오류 재시도 대기를 우선하며 재시작 후에도 유지한다.
  잔여 호출량으로 평균 간격을 계산하던 자동 pacing은 이 노드에서 비활성화한다.
  이전 자동 pacing 캐시는 무시하되 실제 HTTP 오류 대기는 유지한다.
- 잔여시간 없는 빨강은 원본 12초 동안 대기를 표시하고 3초 이상 간격으로 재시도한다.
  녹색은 유효 잔여시간 없으면 진입 불허다. 정보 만료·통신 실패 후 새 정보가 없으면
  대기/신호 없음(횡단 중에는 기존 주의 정책)으로 처리한다.
- `/crosswalk/guidance.signal_countdown_s`는 빨강 또는 초록의 남은 현시 시간을 뜻한다.
  기존 `signal_remaining_s`는 진입 계산용 녹색 시간이며 빨강에서는 0이다.
  진입 필요시간 `길이/보행속도+3초`, 횡단 중 여유 2초는 유지한다.
  `motion_output_enabled=false`이므로 정책 목표는 모터 명령으로 발행하지 않는다.
  목표속도·PWM·실제 측정속도를 변경하는 작업이 아니다.
- 이 계산은 받은 현시가 보고된 종료 시각까지 유지된다는 가정이며 중간 현장 변경을
  즉시 감지하지 못한다. 미래 주기 학습이나 다음 녹색 시작의 확정 예측은 수행하지 않는다.

## 2026-09-29 병합 후 방향·선택 동작

현재 작업 트리는 `jingyu`의 GPS·자이로 방향 융합과 `pdj1`의 최근접 후보 선택을
함께 유지한다. 아래 최근접 선택이 이전 거리 추세·방향 기반 선택을 대체한다.
방위는 현재 후보 선택에 사용하지 않는다. 기존 `selection_hold_s`,
`selection_margin_m` 설정은 현재 최근접 선택에 사용하지 않는다.

- 방향 기준은 이동 중 GPS course 또는 최소 2m 위치 이동으로 확보하고,
  `/terrain/imu` 회전속도를 roll/pitch 보정해 적분한다. `heading_gyro_sign=1`은
  반시계 양의 ROS yaw이며 반대 장착은 -1이다.
- GPS만 있으면 5초, 연속 IMU가 있으면 마지막 GPS 기준 이후 최대 20초 유지한다.
  IMU 0.35초 초과 단절·시간 역전/중복·무효 입력·roll/pitch 45도 초과 시 방향을
  무효화하고 새로운 GPS 방향 관측으로 복귀한다. 방향 신뢰도는 선택 필수 조건이 아니다.
- 3도/s 초과 회전 중 및 이후 1초간 GPS 보정을 보류하고, 그 외에는 각도 오차의
  20%를 반영한다. 바퀴 정지 및 0.5도/s 미만 자이로가 2초 유지되면 영점을 보정한다.
- `motion_output_enabled=false`를 유지한다. 횡단 정책 목표는 실제 측정속도나
  모터 PWM이 아니며 현재 횡단 정책은 모터 명령을 발행하지 않는다.

## 1. 구분과 단위

속도 변화는 다음 세 종류로 구분한다.

1. **목표속도 변경:** 새 명령과 활성화된 선택 정책으로 목표를 바꾼다.
2. **PWM 보정:** 목표를 유지하면서 실제 속도 오차에 따라 출력을 바꾼다.
3. **감속·정지:** 손 해제, 경사, 지면 위험, 과속, 통신·센서 문제로 출력을 줄인다.

| 용어 | 의미 |
|---|---|
| 목표속도 | 제어기가 따라가려는 속도. 실제 속도와 다를 수 있다. |
| 측정속도 | 왼쪽 Hall 센서의 펄스 간격으로 계산한 바퀴 속도. 오른쪽 값은 복제값이다. |
| Hall 입력 | A3141/A3144 단극성 디지털 출력, Drive D2(INT0), 5V 풀업, HIGH→LOW당 1펄스. 기존 A3 아날로그 기준값/ADC 역치는 사용하지 않음. |
| PWM | Arduino `0~255` 척도의 출력 count. PWM 100은 100%가 아니라 약 39.2% 듀티다. |
| PWM cap | MCU가 계산한 PWM에 적용하는 출력 상한. cap 값 자체가 항상 실제 PWM으로 출력되는 것은 아니다. |
| BRAKE | 코드상 PWM 0 및 방향 핀 LOW/LOW 출력. 실제 정지나 경사 위치 고정을 확인했다는 뜻은 아니다. |
| 보정 후 pitch | Terrain bridge가 평지 기준 pitch -0.116rad, roll -0.059rad를 뺀 `/terrain/status` 각도. **음수=오르막, 양수=내리막**. `/terrain/imu`는 센서 좌표계 원본이다. |

기본 바퀴 반지름은 **0.115m**이며, `선속도 = 반지름 × 각속도`, `km/h = m/s × 3.6`으로 환산한다.
두 모터에는 공통 PWM과 방향 명령을 적용한다. 좌우 독립 속도 제어는 없다.

## 3. 출발과 일반 목표속도 변경

기본 Cruise 요청은 **1.0m/s = 3.6km/h**다. 평지에서 밀기·당기기 의도가 확인되면 **0~1.15m/s** 안에서 목표를 조정한다. 새 목표는 Pi 목표 slew, MCU 목표 ramp, 최종 PWM slew를 거친다.

| 항목 | 설정값 | 의미 |
|---|---:|---|
| 전진 목표 상한 | **1.15m/s = 4.14km/h** | 더 높은 전진 요청을 제한 |
| 후진 목표 상한 | **0.08m/s = 0.288km/h** | 후진 속도 크기 제한 |
| 회전 목표 상한 | **0rad/s** | 현재 회전 명령은 지원하지 않음 |
| Pi 목표 가속도 | **0.50m/s²** | 목표 선속도 상승률 제한 |
| Pi 목표 감속도 | **0.50m/s²** | 정상 목표 선속도 하강률 제한 |
| MCU 목표 가속도 | **6.0rad/s² ≈ 0.690m/s²** | 바퀴 목표 각속도 상승률 제한 |
| MCU 목표 감속도 | **5.0rad/s² ≈ 0.575m/s²** | 정상 바퀴 목표 각속도 하강률 제한 |
| 브리지·MCU 각속도 상한 | **10rad/s** | 기본 반지름에서 1.15m/s |
| 최초 전진 PWM step | 최대 **30count** | 제어 출력과 cap 범위 내의 초기 출력 |
| 정상 PWM 상승률 | **30count/s** | 출력 크기를 높이는 속도 제한 |
| 정상 PWM 하강률 | **60count/s** | 출력 크기를 낮추는 속도 제한 |
| 지형 정지 복귀 PWM 상승률 | **10count/s** | 내리막/활성 ToF 감속 완료 후 제어 출력에 도달할 때까지 적용 |
| 설정상 최종 PWM 상한 | **140count** | 실행 중 양손·Hall 추종 cap을 먼저 적용하고, 그 값과 MCU 상한 중 작은 값 적용 |
| 방향 역전 BRAKE 시간 | **150ms** | 반대 방향 구동 전에 0 출력 유지 |

PWM 30→60은 정상 상승률만으로도 약 1.0초가 필요하다. 첫 Hall 측정 전 평지 cap은 35이고 30→35에는 약 0.17초가 걸린다. 실제 속도 도달 시간은 부하와 센서 피드백에도 영향을 받는다.
새 PWM cap은 slew 중에도 즉시 적용된다.

### 3.1 사용자 밀기·당기기에 따른 적응형 목표

`cruise_command` 노드는 사용자 힘 센서 없이 Hall 바퀴속도, `/terrain/imu`의 전방 가속도, MCU의 `feedback_pwm`를 사용한다. 각 주기마다 아래 세 표 중 **2개 이상**이 같은 방향이면 사용자 의도로 본다.

| 투표 입력 | 앞으로 밀기 | 뒤로 당기기 |
|---|---:|---:|
| 최근 0.50초 Hall 속도변화 | **+0.05m/s 이상** | **-0.05m/s 이하** |
| 최근 0.50초 IMU 가속도 적분값 | **+0.03m/s 이상** | **-0.03m/s 이하** |
| MCU P 속도오차 보정 | **-3PWM 이하** | **+3PWM 이상** |

밀기는 측정속도가 현재 목표보다 0.05m/s 이상 낮지 않을 때만 적용한다. 이는 목표를 못 따라가는 상태에서 목표만 계속 높아지는 것을 막는다. 조건이 계속되면 밀기는 **0.03m/s씩 0.40초마다**, 당기기는 **0.05m/s씩 0.30초마다** 반영하며, 두 방향이 동시에 성립하면 당기기를 우선한다.

적응은 MCU 연결·ARM·양손 접촉·Hall 속도가 모두 유효하고, 감독 명령이 `DRIVE`이며, 보정 후 경사가 **±3° 이내**, `slope_ff_pwm=0`, BRAKE·fault가 아닐 때만 허용한다. 이 조건을 벗어나면 목표를 새로 배우지 않지만, 이미 배운 목표는 그대로 유지해 경사 보조와 안전 감독을 받는다. 처음부터 경사면이면 기본 1.0m/s를 사용하고, 나중에 평지에서만 적응을 재개한다.

GPS 속도는 즉시 밀기·당기기 판정의 필수 조건이 아니다. Hall 변화가 작은 상태에서 GPS와 Hall이 **0.40m/s 초과로 2.0초** 지속해 다른 외부 요인이 의심될 때만 새 적응을 잠시 막는다. GPS가 없거나 오래됐어도 나머지 입력으로 작동한다. 양손을 놓으면 적응 목표를 **1.0m/s**로 초기화한다.

이 목표 적응은 안전 감독 앞단에서 요청값만 바꾼다. 경사 감속, 손 해제, 과속, 통신·센서 정지는 여전히 안전 감독과 MCU가 우선한다.

### 3.2 양손 접촉 출발과 Hall 속도제어 PWM cap

별도 모드 선택이나 사용자 수치 입력은 없다. 정상 전진 명령 중 양손 접촉이 처음 확인되면 평지에서 ROS 감독 노드는 `drive_pwm_cap=35`를 보낸다. MCU 최초 전진 step은 최대 30count이고 이후 30count/s로 증가한다. 확정 오르막에서는 출발 cap에도 양수 경사 FF를 추가하되 Hall 속도 무효 시 MCU 출력 후보는 최대 60이다. 실제 출발 여부는 부하와 마찰에 따라 달라진다.

출발 뒤에는 왼쪽 Hall 속도와 마지막 펄스 나이로 출력 상한을 자동 조정한다. 바퀴 반지름 0.115m와 자석 12개이므로 자석 한 칸의 이동거리는 약 **0.0602m**다. 이미 바퀴가 움직이며 ARM한 경우에는 초기 30count step을 넣지 않고 정상 30count/s PWM 상승률을 적용한다.

2026-09-27 센서 변경: D2 인터럽트로 5ms 제어 주기 사이의 짧은 LOW도 검출한다. LOW 유지/해제 및 부팅 시 이미 LOW인 상태는 새 펄스가 아니다. 20ms 이내 재진입은 기존처럼 거부한다. AVR의 32비트 펄스·시간은 원자적으로 복사하고, 무펄스 나이는 포화시켜 장기 정지 중 타이머 순환이 신선한 속도로 보이지 않게 한다. 회전당 12펄스 및 모든 속도·출력·고장 역치는 보존한다. 단극성 센서이므로 실제 한 바퀴에 12펄스가 나오는지 새 장착에서 확인해야 하며, 기존 `HALL_CALIBRATED=true`만으로 확인을 대체하지 않는다.

```text
유효 속도 = min(Hall 측정속도, 0.0602 / 마지막 펄스 나이)  # 나이가 0보다 클 때
평지 PWM cap = round(35 + 25 × clamp(유효 속도 / 1.0, 0, 1))
최종 PWM cap = min(설정 상한 140, 평지 cap + 양수 오르막 FF)
```

평지에서 펄스 나이가 짧아 측정속도를 그대로 쓸 수 있을 때의 예시는 다음과 같다. 이는 **PWM 상한**이며 실제 출력값은 MCU의 FF/P 계산, 출력 slew와 안전 조건에 따라 더 작을 수 있다.

| Hall 유효 속도 | 평지 PWM cap |
|---:|---:|
| 0m/s, 아직 새 펄스 없음 | 35 |
| 0.25m/s | 41 |
| 0.50m/s | 48 |
| 0.75m/s | 54 |
| 1.00m/s 이상 | 60 |

사용자가 감속해 새 자석 펄스가 늦어지면 `0.0602 / 펄스 나이`가 작아지므로 cap도 35 쪽으로 내려간다. 예를 들어 저장된 Hall 속도가 0.50m/s여도 새 펄스가 0.24초 동안 없으면 유효 속도 상한은 약 0.251m/s이고 평지 cap은 약 **41**이다. 따라서 MCU의 5초 동안 저장되는 속도값만 믿고 높은 출력을 유지하지 않는다.

양손을 잡고 ARM을 기다리거나 내리막 정지가 유지되는 동안에는 출발 보조의 4초를 소진하지 않는다. ARM 상태에서 양수 DRIVE를 시작한 뒤 유효한 움직임이 **4초** 동안 전혀 없거나, 움직임 확인 뒤 마지막 펄스 나이가 **4초**에 도달하면 cap을 **0**으로 만든다. 이는 기존 MCU의 Hall 스톨 최소 판정시간 5초보다 먼저 실제 출력을 0으로 내려 정지 중 모터 통전과 Hall FAULT를 피하기 위한 ROS 측 제한이다. 한 번 시작한 4초 시계는 같은 양손 접촉 중 ARM 토글로 다시 열리지 않는다. 손을 놓았다 다시 잡으면 새 출발 보조가 열리고, cap 0 상태에서도 사용자가 밀어 새 유효 펄스가 들어오면 속도 추종 보조가 재개된다.

이 cap 기능은 위 3.1의 적응형 목표와 별개다. 적응형 목표가 제어기가 따라갈 속도를 바꾸고, Hall 동적 cap은 실제 출력 상한을 35~60 범위로 조정한다. MCU의 FF/P 속도 제어와 직렬 메시지 형식은 유지한다.

일반 요청속도 **0은 즉시 BRAKE**다. 손 해제 fade 또는 지형 감속 모드는 별도 경로로 처리한다.
매우 작은 적용 목표 `|각속도| <20mrad/s`에서는 출력이 0으로 처리된다. 선속도로는 약 **0.0023m/s**다.

일반 DRIVE·BRAKE·TERRAIN_STOP 모두 ARM 조건을 공통으로 검사한다. 기본 경로는 필터 측정속도가 **100mrad/s 이하**인 상태를 **250ms** 유지하는 것이다(반지름 0.115m에서 약 **0.0115m/s**). 추가로 Hall 펄스가 두 개 이상이고 마지막 펄스 나이가 **0.75초 이하**, 펄스 간격이 **174533µs 이상**인 느린 이동 중에는 양손 접촉·유효 통신·고장 없음 조건 아래 ARM할 수 있다. 이는 약 **0.345m/s 이하**에 해당하며, 그보다 빠르거나 첫 펄스뿐이면 이동 중 ARM을 거부한다. Hall은 회전 방향이나 물리적 정지를 직접 증명하지 못한다. 유효 명령을 거부하는 동안에는 추진 허가를 갱신하지 않지만 통신 세션 활동시간은 갱신해 ARM 대기를 세션 손실로 처리하지 않는다.

근거: [Pi 설정](../config/raspberry_pi.yaml), [Drive 설정](../firmware/safestride_mcu/config.h), [MCU 제어 호출](../firmware/safestride_mcu/safestride_mcu.ino).

## 4. 오르막: 목표 유지와 추가 PWM

Terrain bridge는 `/terrain/status`의 pitch에서 평지 기준 **-0.116rad**를 빼고 roll에서 **-0.059rad**를 뺀다. 감독의 `pitch_offset_rad=0`, `uphill_pitch_sign=-1`이므로 보정 후 음수 pitch는 오르막이다. `/terrain/imu`는 보정되지 않는다.

| 보정 후 경사·지속 조건 | 목표속도 변화 | 추가 경사 PWM |
|---|---|---|
| 오르막 5° 미만에서 평지 진입 | 배율 1.0 | 0 |
| 오르막 **5° 이상, 0.5초 유지** | 오르막 확정, 배율 **1.0** | 아래 식 적용 |
| 확정 후 오르막 **3° 초과~5° 미만** | 배율 1.0 | 0 |
| 오르막 **3° 이하, 0.5초 유지** | 평지 분류 복귀 | 0 |

경사 진입 전에 적응한 요청 속도는 오르막에서도 그대로 유지하며 경사 중에는 새로 적응하지 않는다. 적응 전에 오르막에 진입했다면 기본 **1.0m/s**를 사용한다. 전진 목표 상한 1.15m/s는 유지되며, 후진에는 전진용 경사 FF를 적용하지 않는다.

```text
추가 경사 PWM = round(clamp(7.5 × (오르막 각도_deg - 3), 0, 45))
적용 조건: 확정 오르막 상태 + 오르막 각도 5° 이상 + 전진 구동
```

| 오르막 각도 | 추가 PWM |
|---:|---:|
| 5° | +15 |
| 7° | +30 |
| 9° 이상 | +45로 제한 |

FF는 목표속도가 아니라 PWM 출력 후보에 더한다. 실제 속도 상승량은 부하와 Hall 피드백에 따라 달라진다.

근거: [경사 정책](../src/safestride_control/safestride_control/safety_logic.py), [감독 노드](../src/safestride_control/safestride_control/safety_supervisor_node.py).

## 5. 내리막: 임계값 진입부터 2.5초 PWM 감속

| 보정 후 pitch 조건 | 반응 |
|---|---|
| 평지에서 **+7° 미만** | 경사 감속 시작 없음; +5° 내리막 분류와 감속 조건 분리 |
| **+7° 이상 첫 유효 측정** | 다음 감독 주기에 `TERRAIN_STOP`; 실제 PWM에서 즉시 2.5초 선형 감속 시작 |
| 감속 진입 후 **+3° 초과** | 동일한 감속 유지; 7° 아래로 내려가도 즉시 재가속하지 않음 |
| **+3° 이하 유효 상태 0.5초 유지** | 복귀 허용. 이미 시작한 감속은 2.5초까지 완료하고 10count/s로 보조 회복 |

현재 실행 설정의 `downhill_speed_scale=1.0`은 유지한다. 7° 진입 시 전송 목표속도는 0m/s이나 MCU는 별도 감속 모드로 직전 실제 PWM을 저장하고 `시작 PWM × (1 - 경과시간/2.5초)`로 줄인다. 예를 들어 시작 PWM이 60이면 1초 후 36, 2초 후 12, 2.5초 후 0이다. 반복 명령은 감속 타이머를 다시 시작하지 않는다. PWM 감소는 추진력 감소이며 실제 이동속도가 같은 비율로 감소하거나 2.5초 뒤 정지한다는 보장은 아니다.

IMU 무효·통신 기한 초과·명시적 비상정지는 2.5초 감속을 기다리지 않는다. 내리막 정지 요청이 계속되면 감속 완료 후 PWM 0을 유지한다. 방향 핀 LOW/LOW는 기계식 경사 위치 고정을 보장하지 않는다. 이 변경에는 ROS 브리지와 Drive MCU의 경사 FF 허용 범위를 함께 -60~45로 갱신했으므로 Pi 코드와 Drive MCU 펌웨어를 함께 배포해야 한다.

근거: [경사 분류·조기 정지 정책](../src/safestride_control/safestride_control/safety_logic.py), [감독 구동 명령](../src/safestride_control/safestride_control/safety_supervisor_node.py), [MCU 즉시 정지](../firmware/safestride_mcu/motor_control.cpp).

## 6. 일반 속도 오차: P 제어

부하·마찰·사용자가 미는 힘으로 측정속도가 목표와 달라지면 PWM을 보정한다.

| 유효 Hall 측정 결과 | 반응 |
|---|---|
| 측정속도 < 목표속도 | PWM 증가 방향으로 보정 |
| 측정속도 > 목표속도 | PWM 감소 방향으로 보정 |
| 측정속도 ≈ 목표속도 | 보정량이 작아짐 |

일반 주행에는 '0.1m/s 오차 이상에서 작동' 같은 별도 역치가 없다. 유효한 속도 오차에 비례해 보정한다.

```text
P 보정 = 12 × (목표 각속도 - 측정 각속도)   # rad/s
기본 FF = sign(목표) × [40 + 20 × |목표 각속도| / 8.696]
PWM 후보 = 기본 FF + 경사 FF + P 보정
```

반지름 0.115m 기준 목표보다 0.1m/s 느리면 약 **+10.4PWM**, 빠르면 약 **−10.4PWM** 보정이다.
현재 Ki=Kd=0이며, 목표 반대 방향 출력은 금지한다. 최종 상한과 PWM 변화율 제한이 적용된다.
함수의 작은 속도 예외로 목표 크기 <0.02rad/s 및 측정 크기 <0.05rad/s가 동시에 만족되면 보정값은 0이다.

근거: [FF/P 계산](../firmware/safestride_mcu/motor_control.cpp).

## 7. 절대 과속: 즉시 BRAKE

| 조건 | 반응 |
|---|---|
| 새 Hall 구간속도 **8km/h 초과**, **2회 연속** | 과속 BRAKE |
| BRAKE 이후 새 구간속도 **7km/h 미만** | 과속 BRAKE 해제 가능 |
| 마지막 펄스 이후 **5초 이상** | 무펄스 조건으로 해제 가능 |

8km/h는 약 **2.222m/s**, 7km/h는 약 **1.944m/s**다.
정상 목표 상한 **4.14km/h**와 별개의 보호 역치다. 정확히 8km/h는 초과 조건을 만족하지 않고, 정확히 7km/h는 미만 해제 조건을 만족하지 않는다.

판정은 필터 전 Hall 펄스 간격 속도를 사용한다. 같은 저장값을 반복해서 검사한 횟수는 연속 관측 횟수에 포함하지 않는다.
12자석/반지름 0.115m에서 8km/h의 펄스 간격은 약 **27.1ms**다.
무펄스 timeout은 실제 정지 확인과 다르며, 다른 정지 조건이 남아 있으면 재가속하지 않는다.

현재 MCU는 지형 감속 분기를 먼저 처리한다. **2.5초 지형 감속 경로를 실행하는 동안에는 뒤의 절대 과속 검사 분기가 실행되지 않는다.**

근거: [과속 BRAKE](../firmware/safestride_mcu/motor_control.cpp), [과속 설정](../firmware/safestride_mcu/config.h).

## 8. 손 해제: 약 600ms 감속

| 조건 | 역치 |
|---|---|
| 접촉 진입 | 해당 손의 raw와 필터값이 **모두 35ADC 이상** |
| 접촉 유지 | raw **32ADC 이상** |
| 접촉 해제 확정 | raw **32ADC 미만, 2회 연속** |
| 압력 샘플 주기 | **100ms** |
| 주행 허용 | **양손 모두 접촉** |
| 해제 감속 | 해제 확정 후 약 **600ms** |

해제 판정은 샘플 시점에 따라 약 100~200ms가 걸린다. 한쪽이라도 해제되면 MCU가 직전 실제 PWM과 적용 목표를 줄인다.
완료 후 SAFE_STOP으로 전환한다. 감속 도중 양손 재접촉이 확인되면 감속을 취소하고 새 정상 명령을 받을 수 있다.
통신 기한 초과·고장 등 높은 우선순위 정지는 600ms 완료를 기다리지 않는다.

| 압력 진단 조건 | 반응 |
|---|---|
| 좌우 필터 압력 차이 **300ADC 초과** | WARNING |
| 필터 압력 최대 변화량 **150ADC 초과** | WARNING |

WARNING 자체로 목표속도를 낮추지 않는다. 압력 크기에 비례한 속도 제어도 없다.

## 9. ToF 지면 위험: 현재 모니터링 전용

ToF는 45° 하향 광선 방향의 거리와 고정 기준 지면 거리를 비교한다.

| 항목 | 역치·설정 |
|---|---:|
| 기준 지면 광선 거리 | **442×√2 ≈625.1mm** |
| 위험 거리 차이 | **250×√2 ≈353.6mm** |
| 돌출물 후보 | 필터 거리 **약 271.5mm 이하** |
| 낙차 후보 | 필터 거리 **약 978.6mm 이상** |
| 위험 확정 | 같은 방향 위험 **4회 연속** |
| 샘플 주기 | **50ms** |
| 거리 EMA 계수 | **0.3** |
| 초기 필터 예열 | **10개 측정** |
| 유효 raw 거리 범위 | **100~2000mm** |
| 확정 위험 표시 유지 | 마지막 확정 이후 **1초** |

250mm는 고정 장착 모델에서 수직 높이 차이를 광선 거리로 환산한 값이다.
앞쪽 장애물까지의 수평거리나 정지거리를 뜻하지 않는다.
판정은 필터 거리 오차를 사용하며, `change_mm`는 현재 위험 확정 역치로 쓰지 않는다.

- 현재 `terrain_stop_enabled=false`이므로 후보나 확정 위험 모두 모터 명령을 바꾸지 않는다. 활성화하면 RAISED/DROP 확정 시 2.5초 PWM 감속을 시작한다.
- 4회 연속 측정 확인에 더해 거리 필터 지연이 있다.
- 정지 기능을 활성화한 경우 복귀에는 **유효 NORMAL 0.5초 유지**와 **정지 시작 후 3.1초 이상 경과**가 모두 필요하다.
- 무효 ToF는 새 감속을 시작하지 않으며, 기능 활성화 시에도 기존 위험의 정상 복귀 증거가 아니다.
- 기준 거리는 고정값이다. 초기 예열 중 장애물을 정상 지면으로 학습하지 않는다.

근거: [ToF 설정](../firmware/terrain_mcu/config.h), [ToF 분류](../firmware/terrain_mcu/tof10120_sensor.cpp), [감독 복귀 판정](../src/safestride_control/safestride_control/safety_supervisor_node.py).

## 10. 센서·통신 문제

| 경우 | 역치·조건 | 반응 |
|---|---|---|
| IMU 무효 | `mpu_valid=false`, MPU fault, 비유한 pitch | BRAKE |
| IMU 오래됨 | 측정 telemetry 나이 + 감독 수신 후 나이 **>0.35초** | BRAKE |
| Hall 속도 유효 | period **20ms 이상·5초 미만**, 마지막 펄스 age **5초 미만** | 정상 P 피드백 가능 |
| Hall 첫 펄스 | 아직 두 펄스 간격 없음 | 속도 무효; 위치만 갱신 |
| Hall timeout | 마지막 펄스 age **5초 이상** | 필터 속도 0, `speed_valid=false`, P=0 |
| ROS 보행 보조 무펄스 제한 | 양손 접촉 출발 또는 마지막 유효 펄스 이후 **4초** | `drive_pwm_cap=0`; 새 유효 펄스 또는 손 해제 후 재접촉 시 복귀 |
| Hall 무효 상태의 출력 | 정상 FF/P 경로 | 출력 후보 크기 **최대 60PWM** |
| Hall 스톨 | 적용 목표 크기 **≥20mrad/s**, 직전 출력 크기 **≥0.5PWM**, 무펄스 기한 도달 | Hall FAULT 및 정지 |
| Hall 비현실적 속도 | 필터 속도 크기 **>25000mrad/s**, 새 펄스에서 **2회 연속** | Hall FAULT 및 정지 |
| MCU 명령 watchdog | 새 수락 명령 이후 현재 TTL **200ms 초과** | 즉시 SAFE_STOP 및 세션 무효 |
| MCU 세션 활동 중단 | **1초 초과** | 세션 해제 및 정지 |
| 브리지 telemetry 오래됨 | **0.30초 초과** | disable 명령 |
| 브리지 목표 오래됨 | **0.50초 초과** | disable 명령 |
| 감독 목표/상태 오래됨 | 각각 **0.50초 초과** | 정지 및 명령 스트림 차단 |
| 감독 Drive telemetry 나이 | **0.50초 초과** 또는 비유한/음수 | 정지 |
| AVR 주 루프 정지 | 하드웨어 watchdog **500ms** | MCU 재설정 |
| 수동 inhibit/명시적 BRAKE | 서비스 enable 차단 또는 BRAKE 명령 | 즉시 정지 |

Hall 무효의 최대 60 제한은 **출력 후보**에 적용된다. 이미 높은 출력이면 최종 PWM은 정상 하강 slew로 내려간다.
**Hall 측정 무효는 즉시 스톨 FAULT와 같지 않다.**

스톨 기한은 다음과 같다.

```text
스톨 기한 = clamp(예상 자석 펄스 간격 × 2.5, 5초, 10초)
```

25000mrad/s는 기본 반지름에서 약 **10.35km/h**다.
이 검사는 필터 속도 기반의 latched FAULT이고, 8km/h 검사는 필터 전 구간속도 기반의 자동 해제 가능한 BRAKE다.
Hall FAULT는 disabled 명령과 물리적 reset-safe 조건에서 해제하는 절차가 필요하다.

MCU가 수락하는 TTL 범위는 **20~250ms**이며 현재 Pi가 **200ms**를 전송한다.
잘못된 CRC·세션·순번·명령값은 watchdog 시각을 갱신하지 않는다.
복귀에는 문제 해소뿐 아니라 세션, 새 명령, 양손, fault 해제, ARM 조건도 필요할 수 있다.

## 11. 현재 비활성인 선택 기능

| 기능 | 활성화했을 때의 역치·정책 | 현재 상태 |
|---|---|---|
| 전방 장애물 거리 | **≥0.80m** 정상, **0.35~0.80m** 선형 감속, **≤0.35m** BRAKE | 실제 전방 센서 미구현, `range_control_enabled=false`이므로 현재 명령 미반영 |
| 노면 분류 | confidence **≥0.55**, top1-top2 **≥0.08** | `surface_control_enabled=false`; 신뢰도 채택 조건만 완화, 분류 라벨·학습 가중치 불변 |
| 노면 속도 배율 | wet **×0.85**, gravel/block **×0.95**, snow/ice **×0.75**, step/hole **×0**, smooth/rough 등 **×1.0** | 현재 목표에 반영하지 않음 |
| 횡단보도 요청 | WAIT_AT_CURB **0**, 접근/이탈 최대 **0.50m/s**, 기본 안전속도 **1.00m/s**, 최종 보조 상한 **1.15m/s** | `motion_output_enabled=false` |
| 자석 시험 모드 | 최근 펄스 **750ms 이내** 창에서 고정 **60PWM** | `MAGNET_BENCH_MODE=false` |
| E-stop | 디지털 입력 활성 시 즉시 정지 | `ENABLE_ESTOP=false` |
| 드라이버 fault | 디지털 fault 입력 활성 시 FAULT·정지 | `USE_DRIVER_FAULT_PIN=false` |
| 배터리·전류 | 선택 telemetry | 현재 센싱 꺼짐. 저전압 속도 보상/전류 제한 제어 없음 |

전방 거리 배율은 `(거리-0.35)/(0.80-0.35)`다. 예를 들어 0.575m이면 배율 0.5다.
노면/경사 중 하나가 감속 배율이면 두 값 중 작은 값을 사용한다. 둘 다 증속이면 곱하되 **1.25**로 제한한다.
현재 GPS는 MCU 속도 P 루프의 입력이 아니며, 횡단보도 요청 출력도 꺼져 있다.
횡단보도 정책의 프로필 표본이 없을 때 기본값은 **1.00m/s**이고, 실제 이동 표본이 있으면 중앙값을 최대 1.00m/s로 제한해 사용한다. 일반 횡단은 프로필 속도와 측정속도 중 큰 값을 요청하며 긴급 횡단은 프로필 속도에 0.10m/s를 더하되 **1.15m/s**를 넘지 않는다. 진입 가능시간에는 사용자 반응 **1초**, 신호 종료 전 안전여유 **2초**가 포함된다. 이 값들은 상태 메시지 계산에는 사용되지만 `motion_output_enabled=false`인 현재 설정에서는 모터 명령을 바꾸지 않는다.

## 12. 실행 순서와 해석 시 주의점

1. Drive Uno의 물리 정지·fault·watchdog 및 최종 출력 허용조건이 출력 가능 여부를 결정한다.
2. 출력 허용 상태에서도 명시적 BRAKE는 정상 PWM slew보다 우선한다.
3. 지형 감속은 정상 FF/P 제어를 우회한다. 감속 중 출력을 추가하지 않는다.
4. 지형 감속 분기는 절대 과속 검사보다 앞에 있어, 해당 분기 실행 중에는 뒤의 과속 검사를 하지 않는다.
5. 정상 손 해제는 자체 fade 경로를 사용하며, 더 높은 우선순위 정지는 즉시 출력을 0으로 만든다.
6. 정상 구동에서만 목표 ramp, FF/P, 양손·Hall 기반 동적 출력 cap, PWM slew로 속도를 추종한다.

모든 각도 역치는 **MPU 가속도 기반 pitch의 필터값** 기준이다. 경사 제어용 자세 계산은 자이로 융합을 사용하지 않는다. 횡단보도 방향 추적은 위 절의 별도 GPS·자이로 융합을 사용한다.
따라서 장착 보정, 필터 응답, 가감속·충격에 따른 각도 변화가 판정 시점에 영향을 준다.
목표속도·PWM·감속 시간은 코드 동작을 설명하는 값이며 실측 속도·제동거리와 구분한다.
