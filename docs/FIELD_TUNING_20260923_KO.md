# 2026-09-23 현장 피드백 반영

## 내리막과 노면

- 보정 후 내리막 +7도 첫 유효 측정부터 실제 PWM을 3초에 걸쳐 0으로 줄인다. +5도 내리막 분류는 감속을 시작하지 않는다.
- 예: PWM 60에서 시작하면 1초 40, 2초 20, 3초 0. 이는 바퀴 속도 보장이나 경사면 제동 보장이 아니다.
- 손잡이 해제, 통신 끊김, IMU 무효, 비상정지는 기존 즉시 정지 우선순위를 유지한다.
- 노면 confidence 0.65→0.55, top1-top2 차이 0.15→0.08. 모델 재학습이나 smooth 강제 선택은 하지 않았다. rough로 오분류하는 현상 자체는 촬영 데이터로 추가 평가해야 한다.
- 노면 결과의 모터 제어 반영은 기존처럼 비활성이다. 출발·오르막 보조는 이전 커밋 1c0ee16 설정을 유지한다.

## 횡단보도 신호

- 통합 API에서 선택 방향 신호가 유효하면 다른 방향에 누락된 신호가 있어도 해당 응답을 사용한다. 선택 방향이 없거나 불명확하면 기존 API로 재조회하며 다른 방향 신호로 대체하지 않는다.
- 교차로 또는 방향이 변경되면 기존 3초 조회 간격을 기다리지 않고 다음 가능한 조회를 시작한다. 이미 진행 중인 요청은 중복 실행하지 않고 완료를 기다린다.
- 교차로/방향 선택 기준은 임의로 완화하지 않았다. 신호 응답 유무만으로 다른 횡단보도를 선택하지 않는다.
- 진단은 교차로 미매칭, 새 교차로 조회 대기, 신호 현시/방향/시간 오류와 API 오류를 구분한다. 유효하지 않은 현시 이유를 통신 오류 문구로 덮어쓰지 않는다.

```bash
ros2 topic echo /crosswalk/status
ros2 topic echo /crosswalk/guidance
ros2 topic echo /diagnostics
```

`/diagnostics`의 `signal_reason`, `intersection_id`, `signal_direction`, `signal_phase_value`, `signal_raw_countdown`을 실제 신호와 대조한다.

이번 수정은 신호 조회 경로의 확인 가능한 오류를 수정한 것이다. 현장 교차로의 API 제공 여부나 자동 방향 매칭이 정확하다고 검증한 것은 아니다. GPS 오차, 중심점 기반 교차로 매칭, 진행축에서 추정하는 신호 방향은 여전히 현장 검증 대상이다. 신호 데이터가 있는 다른 횡단보도를 임의로 선택하지 않는다. 검증 전에는 화면의 진입 안내를 도로 횡단의 근거로 사용하지 않는다.

## 배포

이 변경은 ROS 코드/설정 변경이다. Pi에서 pdj1을 업데이트하고 ROS 패키지를 다시 빌드한 후 실행 노드를 재시작해야 한다. 이전 1c0ee16의 3초 PWM 감속 펌웨어가 Drive MCU에 업로드되어 있어야 하며, 이번 변경만으로 MCU에 자동 배포되지는 않는다. 모터 출력을 분리한 상태에서 6.9도 DRIVE, 7도 TERRAIN_STOP 전환을 먼저 확인한다.
